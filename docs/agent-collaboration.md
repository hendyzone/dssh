# 可选 Agent 协作：taskboard 与 amail

从零创建 worktree、tmux 会话和独立邮箱，见 [Agent 操作手册](agent-playbook.md)。
agent 已在 tmux 内运行时，同一手册提供“接入运行中的 agent”流程：复用会话/worktree，不要求重启或重新创建。

## 把手册发给 Agent

在 **设置 → Agent 协作 → 发给 Agent 的操作手册** 选择“Agent 已在 tmux 中运行”或“新建 worktree 和 Agent”，
点击 **复制给 Agent**，再粘贴到目标 agent 的对话；也可点击 **保存 Markdown** 选择本机文件路径。
手册在构建时内置，未连接服务器、未启用协作或离线时均可使用。
已启用的协作面板也提供“发送接入手册给 Agent”入口。

复制和保存包含完整手册及接入指令。当前选择了会话/worktree 时，会附上表单里的项目、会话与邮箱目录等信息，
但这些值仍须核对，且不包含密码、令牌文件内容或令牌路径。不会自动向终端粘贴、按回车或发送邮件。
可展开查看完整 Markdown；剪贴板不可用时可手动选择文本复制。

dssh 可通过现有 SSH 连接查看共享任务看板、交接记录和 agent 邮件，并预览、发送或回复结构化消息。
此功能默认关闭，按 **tmux 会话 + Git worktree** 配置；任务看板和通信可分别启用。
绑定键由服务器、tmux ID、会话创建时间和 worktree 的真实根目录组成。SSH 重连不会改变绑定；
同名重建会话、另一个会话或另一个 worktree 不会沿用原绑定。

## 开启

1. 通过 dssh 的 tmux 列表打开会话，在该会话中进入目标 worktree。
2. 打开 **设置 → Agent 协作**，选择已连接的 tmux 会话，点击“读取当前 worktree 配置”，填写项目编号。
3. 根据需要勾选任务看板、Agent 通信并填写对应路径和地址。
4. 勾选“开启此会话 + worktree 的 Agent 协作”，点击“保存协作配置”。
5. 从当前会话的终端工具栏打开 **Agent 协作**。

只保存未启用的配置不会产生远端请求。关闭总开关并保存后隐藏工具入口和面板，
停止后续查询；关闭前已经提交的远端操作可能仍会完成。
损坏、不完整或旧版缺少字段的配置按关闭处理，不会因升级自动开启。v1 服务器级配置留在本机，
v2 不读取或自动扩散这些绑定。需要为每个会话/worktree 重新配置；普通 SSH 标签页不提供此入口。

## 配置含义

| 字段 | 说明 |
| --- | --- |
| 项目编号 | 与 taskboard 中的 slug 一致；amail 消息使用同一项目编号 |
| tmux 会话 | 已连接会话的 ID 和创建时间；名称仅用于显示 |
| worktree 根目录 | 点击读取自动取得 Git 根目录及真实路径；支持独立 worktree 和主工作区，不支持裸仓库 |
| 看板服务地址 | **SSH 服务器可访问**的 HTTP(S) URL，不是从桌面浏览器访问的地址 |
| taskboard 命令 | 远端 PATH 中的程序名或实际可执行文件绝对路径；不要填写整条 shell 命令 |
| 远端令牌文件 | 可选，只保存文件路径；内容不读取到桌面或写入命令参数 |
| Python 命令 | 远端 Python 3 的程序名或绝对路径，例如 `python3` |
| mailctl.py 路径 | 远端 amail 客户端的绝对路径 |

配置仅保存在当前设备，不纳入现有 GitHub 连接备份。另一台设备需要单独配置并开启，
避免恢复连接后自动访问服务。无需将邮箱密码或看板 token 输入 dssh。

amail 使用每个绑定的独立身份目录：`<worktree>/.dssh/agents/tmux-<数字ID>-<创建时间>/.agent-mail/env`。
设置中显示该会话邮箱目录；使用已有 mailctl provision 的 `--dir` 指定这个目录建立身份。
运行在同一会话/worktree 的 Claude/Codex/pi 可把 `AGENT_MAIL_HOME` 指向同一目录，使用同一邮箱。
不要将 `.dssh/agents/` 的身份文件提交到 Git。dssh 不创建邮箱或复制旧工作区的身份，
也不把默认运维邮箱自动分配给各会话。邮件中的 session 由 tmux 身份和 worktree 派生，不使用临时 SSH 连接 ID。

## 远端前提

- taskboard 客户端与服务端需包含 [taskboard-service PR #1](https://github.com/hendyzone/taskboard-service/pull/1) 的 `agent context` 接口。
- amail 客户端需包含 [amail PR #1](https://github.com/hendyzone/amail/pull/1) 的 `message send/read/reply`。
- amail 邮箱需要事先配置好，远端可访问 SMTP/IMAP/网关；dssh 不自动开箱、安装软件或启动服务。
- 使用远端非交互 shell 可找到的可执行文件；如果程序仅在交互 shell 的别名中可用，填写实际路径。
- 此版本通过 POSIX 命令调用，不支持 Windows PowerShell 作为远端命令 shell。

## 面板行为

**任务看板**：打开已启用面板时读取一次，之后点击刷新。显示任务状态、有效领取者和项目最近 50 条交接。
点击任务填入任务编号，可筛选当前页交接并用于发信。不提供网页端所有编辑功能，也不自动领取、完成或合并任务。

**Agent 通信**：按按钮查询最近 20 封邮件，输入 UID 读取结构化消息。兼容纯邮箱版 amail，无需花名册或心跳服务。
支持请求、回执、进度、阻塞、交接、结果、提问与回答；回执和回答须回复原邮件。
普通邮件可继续在远端使用原 `mailctl read` 查看。

**发送**：先填写内容并预览实际收件人、项目、任务和正文，再点击“发送预览中的消息”。
修改任意输入会使预览失效。SMTP 返回 submitted 仅表示邮件服务器接受，不表示 agent 已读或任务完成。
发送中断时先检查邮件/回执，避免重复投递；程序不自动重试发送。

## 从 Lead 跳转到成员终端

工具栏的「团队」入口支持跨服务器打开成员的 tmux 会话，不需要预先开启看板或邮箱：

如果选错了 Lead 窗口或项目，点击面板上方的「退出团队」，再切换到正确窗口重新设置。
退出会解除本设备当前 tmux + worktree 的项目协作配置（含该绑定的看板、邮箱设置），其他窗口不受影响；不会停止远端 Agent、删除成员列表或改变 Agent 实际角色。右上角 × 只关闭面板。

1. 在 Lead 的 tmux 窗口点击工具栏「团队」，输入项目名称，点击「打开此项目的团队」。已有协作配置时直接读取团队。
2. 点击「添加成员」，选择已打开的成员终端，名称自动填入，也可以修改；点击「加入团队」。服务器和实际 worktree 自动读取，不需要邮箱或 JSON。目标终端尚未打开时，先连接对应服务器并从 tmux 列表打开它。
3. 在成员卡片点击「打开终端」。dssh 按主机、端口、用户名匹配本机保存的 SSH 连接；地址别名不同或存在多个匹配时，卡片提示选择「本机连接」。选择保存在本设备。

卡片紧凑显示成员名称、服务器和并排的打开、管理按钮。职责、当前任务、备注各显示一行短摘要，每行含标签不超过 20 字；当前任务用主题色加粗，完整备注位于默认折叠的「详细信息」。地址、工作目录、编辑备注、移除及「更新终端」位于「管理」。成员重启或迁移后，在「更新终端」里重新选择会话即可保留成员身份。

成员窗口打开团队面板时，会从本机已绑定的 Lead 工作区读取名单，核对服务器、tmux ID、创建时间及实际工作目录。识别后显示所属团队、备注和「打开 Lead 终端」，不再显示创建团队表单。读取失败会提示连接 Lead 服务器后刷新；新设备须先打开一次原 Lead 的团队。未识别窗口的创建入口折叠在「将当前窗口设为 Lead」中。
旧的邮箱成员记录兼容；高级选项仍支持导入和分享位置 JSON，项目编号必须一致。

### 交给 Lead 批量管理

点击「复制给 Lead 的提示词」，粘贴到 Lead 对话。提示词包含当前项目、Lead 服务器及 worktree、完整 Python 辅助脚本和登记步骤，不包含 SSH 凭据或看板令牌。
Lead 根据已有团队资料核实各机器上的真实 tmux 身份及工作目录，生成成员数据，再用脚本一次合并登记；已有成员不被覆盖删除。你无需拼写 JSON，完成后点击「刷新成员」。
提示词仅复制到剪贴板，不会自动发送消息或执行脚本；剪贴板不可用时展开「查看提示词」手动复制。

成员界面显示和编辑「主要负责」「当前在做」「其他备注」三项可选信息，每项最多 2000 字。提示词要求第一行不超过 15 字，后续行保存详细说明。历史 quota 字段保留兼容，但不展示、不要求填写。
Lead 可以在派工、交付、阻塞或迁移后更新，也可直接在卡片点「编辑备注」。备注不替代 taskboard 状态。
这些字段与成员位置一起保存在远端列表，换电脑也可查看。仅改备注不会覆盖其他客户端更新的终端位置。

提示词提供 `.dssh/team/dssh-members.py` 辅助脚本：`members` 读取、`memberBatch @<UTF-8数组文件>` 批量合并、`memberNotes '<JSON>'` 更新指定身份的备注。
批量更新使用与面板相同的锁和原子写入，整批校验通过才保存；每批 1–100 人。省略备注保留已有值，空字符串清空。已有角色始终沿用 email/id，迁移时不要换身份。

已有连接中的同一 tmux 会话会切到对应标签和分屏窗格；否则新建连接并附加。
打开及重连会核对 tmux ID、创建时间和当前活动窗格的 Git worktree 根目录；会话结束、重建或目录不匹配时拒绝附加，请重新生成并登记位置。
附加后看到的是远端现有终端，不会启动第二个 Agent。tmux 内有多个窗口时，进入该会话当前活动窗口。

成员列表保存在 **Lead worktree 的 `.dssh/team/<项目>.json`**，通过已有 SSH 通道读写，远端需要 Python 3 与 POSIX 系统。
多个客户端更新使用文件锁与原子替换。换电脑后连接同一 Lead 工作区并启用协作，即可读取同一列表；本机仍须有对应服务器的 SSH 连接和权限。
不同 Lead worktree 的列表独立，列表不自动跨工作区同步。位置文件仅包含项目、邮箱、角色、服务器地址、worktree、tmux 身份和更新时间，不包含凭据。
将 `.dssh/team/` 加入项目的 Git 忽略规则；本仓库已忽略。

列表打开时读取一次，可点击「刷新成员」。更新时间表示位置登记时间，不表示成员在线、收到邮件或正在执行任务。
成员重启或迁移后需要更新终端；此版本不自动发现团队或接入 onboard 脚本。移除登记只删除位置，不停止 Agent 或删除邮箱。

## 与终端的边界

面板查询和登记操作走独立 SSH exec 通道，不向当前终端注入文本、不按回车。「打开终端」复用已有标签或创建 SSH 连接附加成员 tmux。
只有当前 tmux 会话存在已开启绑定时，才在连接/目录变化、窗口聚焦及每 5 秒检测一次当前 Git 根目录；
隐藏的应用页面暂停检测，未启用时不自动查询。点击设置中的“读取”是显式的只读发现操作。
看板和邮箱不做定时轮询，隐藏标签页不挂载协作面板。切换绑定会清空任务、邮件结果和待发送预览。
每次查询、预览、发送前，后端再校验 tmux 创建时间与当前 worktree；不匹配则拒绝执行。
从面板离开后不会主动取消已提交的邮件操作；返回结果会被丢弃，不写入新的会话界面。

这是一组可选的桌面入口。agent 自动收信唤醒、任务租约续期、Git 同步和会话交接仍由
taskboard / amail / agent 的既有接入负责，dssh 不接管运行中的 Claude、Codex 或 pi。

## 验证

前端包含默认关闭零调用、坏配置关闭、同机不同会话/创建时间/worktree 隔离、旧配置不继承、
重连和过期发现响应、开启后读取、预览/发送测试；Rust 检查 tmux/worktree 校验、身份稳定性、
邮箱目录隔离、开关、参数校验、shell 引号和清除继承凭据。
页面在模拟服务中验证，不代表生产 SSH、看板或邮箱已连接。

团队列表按当前任务摘要分为「工作中」「空闲」「待确认」，并显示人数与状态标签。状态来自 Lead 备注，不代表实时进程活动。提示词要求 currentTask 首行以这三种状态之一开头；仍有任务但阻塞、等待验收的归工作中，确认无任务才归空闲。兼容以「空闲」「待命」或任务号（如 T762）开头的旧摘要，无法识别的保留为待确认。

跨设备迁移：新版「设置 → 同步」完整备份包含团队绑定、成员连接映射和团队面板位置。恢复时会将团队所引用的服务器 ID 转换为新设备的连接 ID。原设备升级后需重新上传一次，新设备使用新版恢复，再连接 Lead 服务器即可读取远端成员和备注；旧备份不含这些入口。同步仍是手动上传/恢复，不会持续同步，也不会复制远端工作区文件。

成员窗口支持「将当前窗口设为 Lead」。先将名单迁移至新 Lead 的真实 worktree，点击入口后会读取目标名单、验证当前成员身份和位置，并展示服务器、目录及成员数；确认时重新核验后保存本机绑定。目标名单为空或身份不匹配会阻止接管。此入口不复制名单、不删除旧绑定、不结束旧 Lead；核实新团队后可在旧窗口退出团队，再上传完整备份供其他设备恢复。
# 团队动态云端摘要

设置 → 云端摘要预置硅基流动、DeepSeek、OpenRouter 和自定义 HTTPS 接口。新配置默认 Responses，可切换 Chat Completions，旧配置保留原协议。填写 API Key 后点击「拉取模型列表」，从下拉框选择，也可手动填写模型 ID。模型列表不代表每个模型都支持当前协议；硅基流动官方文档目前列出 Chat Completions，Responses 不可用时应切换协议。拉取列表只访问同一 API 前缀的 /models，不发送终端内容，也不自动保存输入的 Key。服务商接口参考：[硅基流动](https://docs.siliconflow.cn/docs/api/chat-completions-post)、[DeepSeek](https://api-docs.deepseek.com/)、[OpenRouter](https://openrouter.ai/docs/quickstart)。

Lead 团队面板直接展示团队动态，默认选择前 10 位成员。点击「开启自动总结」，确认发送范围后立即总结，并每分钟更新。成员选择、接口信息和可选的手动预览都在默认折叠的「设置与详情」里。暂停后重新开启无需重复确认本次面板内未变化的发送范围；模型、成员身份或范围变化后重新确认。读取的是 tmux 当前活动窗格的最近输出，最多 6000 字；过滤常见凭据，但不能保证识别业务日志里的全部敏感数据。不会向终端发送命令或自动派工。

结果按工作中、等待处理、空闲、待确认展示，每条摘要最多 20 字，证据和更新时间默认折叠。摘要是模型推测，超过 5 分钟归为待确认；无新输出不代表空闲。可确认开启每 60 秒自动刷新，未变化的输出不请求模型，关闭面板或恢复配置后停止。跨设备通过远端采集租约避免重复请求，租约最多 3 分钟过期。

摘要保存在原 Lead 工作区的团队名单中，与人工备注独立；团队读取同一份名单才能跨设备看到摘要。成员迁移、会话重建后需重新采集，失效采集不会把旧摘要写入新终端。

供应商配置、接口协议、模型和各供应商已保存的 API Key 随「加密上传完整备份」同步。Key 在本机系统凭据库保存，仅在加密备份内携带，恢复到另一台设备的凭据库，不进入界面 localStorage。原设备需重新上传新备份；旧备份仍能恢复，但不含模型配置。自动采集的开启状态和选择成员不会同步。

维护名单的脚本必须使用支持 `aiSummary`、`aiStatus`、`aiUpdatedAt`、`aiDigest`、`aiSource`、`aiEvidence` 的新版本；旧版脚本重写名单会丢弃这些字段。Lead 人工维护职责和任务即可，不应伪造模型采集字段。

Responses 请求与返回结构参考 [OpenAI Docs](https://developers.openai.com/api/docs/guides/migrate-to-responses)；通过 output 中的 assistant message/output_text 提取文本，拒绝未完成结果。

模型配置支持同一供应商的多套独立账号：顶部切换已保存配置即可启用，点击新增配置后填写名称和新的 Key，保存后启用。Key 状态只显示已保存、未配置、检查中或读取失败，不回显密钥；新输入的 Key 会标记尚未保存。新配置使用独立 ID 保存凭据，旧配置继续读取原有凭据。协议、配置名称、ID 和各套独立 Key 均随加密备份同步；升级后重新上传备份才能带上新增配置。删除单套配置及其 Key 不影响其他账号。

同一 Lead 改用另一 IP、端口或连接条目时，团队面板会尝试恢复入口：以已有 Lead 配置的 tmux ID、创建时间和真实工作区为候选，直接通过当前 SSH 连接读取远端名单，并核对名单中的当前会话。仅恢复团队入口和此成员的本机连接映射，不复制名单，也不继承另一连接的邮箱或看板设置。旧地址不必保持连接；有多个候选团队时需要选择。缺少旧配置、名单不存在或会话已重建时不自动关联。明确退出的本机入口不会再次自动恢复。
