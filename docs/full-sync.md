# 完整加密同步

所有参与同步的电脑先更新到支持完整备份的版本。在原电脑打开「设置 → 同步」，填写仓库、访问令牌和同步密码，点击「加密上传完整备份」。另一台电脑使用同一仓库和同步密码，点击「从 GitHub 恢复完整备份」。

完整备份包含连接名称、地址、分组、认证方式、已保存的 SSH 密码、连接引用的私钥文件及口令、端口转发规则、主题、字体、面板左右位置、左栏宽度、空文件夹、排序和折叠状态。

文件在本机使用 Argon2 派生密钥和 AES-256-GCM 加密后上传，随机盐和随机 nonce 每次重新生成。GitHub 上的 `dssh-sync.json.enc` 不含明文连接配置、密码和私钥。同步密码不写入备份。

恢复时，密码与私钥口令写入系统凭据库；私钥写入应用配置目录下新生成的 `sync-keys` 子目录，并自动更新连接路径。Windows 目录权限限制到当前账户，Unix 使用目录 0700、文件 0600。备份中的原始路径不会用作写入目标。

恢复会替换本机连接列表，不合并。新的凭据和私钥准备完成后才替换列表；失败时清理本次准备的数据。原连接列表保存在 `servers.json.bak`。主题和布局会立即应用，不会重建已打开的 SSH 终端。

旧版仅含连接列表的备份仍可读取，但无法凭空恢复其中没有的密码、私钥或界面配置。需要在原电脑用新版重新上传一次。新版完整备份不能被旧版客户端读取。

另一台电脑仍需提供 GitHub 访问令牌和同步密码以读取备份。正在运行的 SSH/tmux 进程不属于配置备份，不会迁移。只备份本机已经保存的登录凭据；配置引用的私钥文件或标记为已保存的凭据无法读取时，会停止上传并提示修正，不会静默生成缺失内容的备份。

为适配 GitHub 内容接口，当前加密文件限制为 900 KB，单个私钥文件限制为 128 KB；超过限制会停止上传并显示错误。
