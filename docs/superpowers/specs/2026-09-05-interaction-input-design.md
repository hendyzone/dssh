# 交互与输入体验优化

用户已确认整体范围：终端焦点、中文输入保护、快捷键和服务器表单。

## 行为约定

- 切换标签或分屏后，将焦点交给当前终端的隐藏 textarea；异步初始化完成的后台终端不得抢焦点。
- 弹窗和标签重命名期间暂停终端自动聚焦；关闭后恢复当前终端输入。点击终端仍可选择文本。
- 弹窗打开后获得初始焦点，Tab / Shift+Tab 在弹窗中循环；设置窗口支持 Esc 关闭（同步处理中除外）。
- 输入法组合期间（isComposing 或 keyCode 229），选词按键不触发应用快捷键、重命名提交或表单提交。
- Ctrl+Tab / Ctrl+Shift+Tab 循环切换标签。应用快捷键在普通输入控件和弹窗中不操作会话；终端内的应用快捷键不发送给远端，普通 Ctrl+C / Ctrl+D 等保持原语义。
- 表单验证非空地址、用户名，1–65535 的十进制整数端口，私钥认证的非空路径。错误显示在对应字段并聚焦首个错误；保留输入。
- 保存返回 Promise，期间禁用字段和重复提交、取消操作；失败就地提示并允许重试，成功才关闭表单。空密码仍表示保持已存凭据。
- 新建和编辑的默认名称使用去掉首尾空白的用户名与地址；编辑保留原端口转发配置。

## 实现边界

保持 React + Tauri 现有结构。共享键盘判定函数供 App 与 TerminalView 使用。ServerForm 自己管理校验和保存状态；App 负责持久化及成功后的列表和会话更新。新增测试只模拟 Tauri/终端运行时边界，实际渲染组件验证输入事件。

终端输入隔离放在键盘和粘贴等 DOM 入口；onData 还承载 DSR 协议回复，后台或弹窗覆盖时也必须保持发送，避免远端 shell 等待回复。

## 验证

回归覆盖：中文选词、正反向标签切换、表单快捷键隔离、异步后台初始化、弹窗焦点恢复、校验边界、重复提交、保存失败重试。运行前端测试与生产构建。真实 Windows 输入法与 SSH 回显需要原生环境实测，模拟 DOM 测试不替代该验证。
