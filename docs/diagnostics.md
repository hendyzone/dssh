# v1.0.1：回到 Tauri 并排查输入与空白界面

## v1.0.2：修复日志定位的内存越界

用户日志捕获到 `getViewport → getLine → render → renderTick` 的 WASM `memory access out of bounds`。已复现视口读取缓冲区不足：`GRAPHEMES_BUF` 会写出整个字符簇，但旧实现只分配一个 u32。新实现按字符簇长度分配并复用缓冲区，在退出时释放。回归测试直接检查 WASM 写入目标容量，覆盖组合字符、ZWJ emoji、连续输出及滚动；旧实现需要至少 8 字节时仅分配 4 字节，修复后通过。

同时为主窗口增加 `dialog:allow-confirm`，修复日志中的确认弹窗 ACL 拒绝。新版本仍保留诊断导出；若再次卡住，继续导出日志确认是否还有其他故障。

本版本恢复迁移前的 Tauri + Rust 桌面架构、原有构建工作流和连接存储，保留主题扩展。安装版本继续递增至 1.0.1，避免与已安装的 1.0.0 混淆。Electron 试验代码仍可从 Git 历史找回。

开发者工具在正式安装版也可用：打开「视图 → 开发者工具」，或按 F12。界面变空白时打开 Console 查看第一条红色错误；Network 可以检查资源加载情况。原生菜单不依赖 React 界面，因此界面渲染失败时仍可使用。

React 渲染异常会显示错误提示和开发者工具入口。应用启动、版本、操作系统、前端异常及未处理的 Promise 错误会写入本地 `desktop.log`。通过「视图 → 导出诊断日志」保存一个文件，即可发送排查；「视图 → 诊断日志位置」可查看原始路径。日志按约 1 MB 轮换，保留当前和上一份，只在本机保存。不会主动收集终端输入、输出、密码或私钥；异常文本可能含路径等上下文，发送前可以查看。重启应用会断开当前 SSH 连接。

候选框定位改为跟随实际光标更新，而非依赖 ghostty 未发出的 onRender 事件；组合输入期间固定位置，提交后清理残留文字。系统输入法的最终行为仍需实机确认。

旧版白屏与 Electron 黑屏是否同源尚未确认。恢复 Tauri 的目的是减少排查变量，并不代表空白界面的根因已解决。
